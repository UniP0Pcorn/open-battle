# 原型架构

`project.godot` 位于仓库根目录，主场景指向 `client/battlefield/tabletop.tscn`。因此客户端、规则和数据可直接使用 `res://` 引用，无需复制数据或设置插件。

规则层 `rules/movement.gd` 只依赖 Godot 基础类型，不访问场景树。坐标、半径和移动额度统一使用英寸；毫米仅在加载底座时通过 25.4 换算。边界与重叠使用微小浮点容差；切边与底座相切均合法。

客户端负责 JSON 加载、底座状态、输入和程序化绘制。每个底座记录中心位置、半径、已用额度与颜色阵营。拖动时仅更新预览；松开后调用规则层，合法才同时提交位置与消耗。非法、Esc 或窗口失焦都不改变已有状态。再次拖动保留已用额度。距离从底座中心计算，拖动保留点击偏移以防选中时跳动。

每次拖动是一条直线移动指令，不是鼠标轨迹采样。多段拖动累计长度，因此绕行不能用最终位移抵销成本。直线路径由规则层按半个底座半径采样，穿过其他底座时拒绝提交；这为后续矩形地形和视线阻挡提供了可复用的验证入口。原型允许操作双方，每个底座独立移动，不冒充完整 40K 单位规则。

动作记录位于 `rules/command_log.gd`，格式契约位于 `rules/command_schema.gd`。每个动作带有连续序号、执行阵营、动作类型和 JSON 载荷；字段、可用阶段和当前操作阵营由同一契约校验。保存文件、回放器和未来服务器共用这套入口，避免客户端、存档和回放各自接受不同的命令格式。

回放器已经能重建阶段切换、移动、前进、撤退、冲锋、回合、战斗震慑、伤害和危险武器事件；阶段切换使用 `PHASE_ADVANCE` 命令，跳过阶段会被拒绝。移动回放现在复用路径、底座碰撞、桌面边界和矩形地形判定，不能只靠伪造最终坐标通过权威校验。状态快照、规则集版本和服务器权威提交已经存在于会话入口，下一步是把它接到网络房间生命周期。3D 客户端可重用同一英寸制规则，替换屏幕坐标映射即可。
`rules/battle_session.gd` 已把快照、规则集 ID、阶段推进和命令提交组合成纯规则层会话；网络层只需传输命令和快照，不应在连接层复制战斗判定。
`rules/room.gd` 在会话外提供两人房间生命周期和玩家到阵营的映射，传输层可以把它直接包在 WebSocket 或 ENet 上；房间自身不接受未经 `BattleSession` 校验的命令。
`rules/peer_protocol.gd` 固定 P2P 命令、快照、重连和认证包的版本、序列与快照哈希；`client/p2p_transport.gd` 提供 ENet 对等传输入口，`rules/account_identity.gd` 提供离线账户挑战证明。传输层只负责收发和完整性校验，战斗判定仍由 `BattleSession`/`Replay` 完成。
`rules/network_sync.gd` 是主机/客户端共用的同步适配器：主机先核对房间、对端、快照哈希和命令序列，再调用 `Room.submit`；客户端只接受通过内容哈希校验的权威快照。
`rules/faction_rules.gd` 统一读取 profile 的 `abilities`、`faction_abilities` 和 `faction_stratagems`，`ArmyBuilder` 会把它们带入模型；阵营导入只需补数据声明，能力和策略的校验/执行器保持共用。条件能力会按攻击阶段合并事件修正，回放会从模型携带的声明中解析阵营自定义策略；通用策略的临时掩体与自动通过战斗震慑效果由回放状态执行并在回合边界清理。
`rules/faction_rules.gd` 统一读取 profile 的 `abilities`、`faction_abilities` 和 `faction_stratagems`，`ArmyBuilder` 会把它们带入模型；阵营导入只需补数据声明，能力和策略的校验/执行器保持共用。条件能力会按攻击阶段合并事件修正，回放会从模型携带的声明中解析阵营自定义策略；通用策略的临时掩体与自动通过战斗震慑效果由回放状态执行并在回合边界清理，FIGHT 阶段会记录并校验单位近战激活状态。
`rules/account_store.gd` 将经过校验的身份记录写入 Godot `user://`，只保存派生 credential hash，不保存密码明文；大厅启动后可直接加载该身份参与挑战认证。
`client/lobby/lobby_screen.tscn` 是大厅的最小可用界面，桌面按 `M` 打开；它提供账号保存、主机/加入房间和准备操作，所有网络动作仍通过 `P2PLobby`。
`client/network_bridge.gd` 作为 Autoload 跨场景保留大厅连接，桌面进入时会订阅权威快照并调用 `apply_network_snapshot`；网络输入命令的逐项替换仍按动作类型推进。
射击和近战的网络命令可以只携带攻击意图；`rules/network_sync.gd` 在主机按会话序列派生确定性骰子、解析武器能力、目标伤害、危险武器自伤和两侧 FNP 骰面，再交给 `Room`/`Replay` 记录，客户端不能直接指定伤害结果。
部署阶段使用 `rules/deployment.gd`，将底座几何检查与阵营部署区分开：部署时限制在任务给出的纵深内，进入移动阶段后仍可在整张桌面移动。
预备队和深入打击使用 `rules/reserves.gd` 与 `DEPLOY_RESERVE` 命令：单位必须声明 `deep_strike` 并处于 `reserve` 状态，入场时统一检查桌面边界、底座重叠和距敌至少 9 英寸；回放、单机 AI、桌面输入和联机快照共享同一状态字段。
近战阶段会按 `fights_first` 能力建立可接战单位的优先窗口；在首发单位完成激活前，普通单位的近战命令会被回放和桌面入口拒绝，AI 也会优先选择首发单位。
`SCOUT` 命令在首回合指挥阶段执行 profile 声明的斥候 6/9 英寸移动，并复用桌面边界、路径碰撞和距敌检查；单机 AI 会在推进到移动阶段前自动使用。
运输工具使用 `EMBARK`、`TRANSPORT_MOVE` 和 `DISEMBARK` 命令；模型通过 `embarked_in` 绑定运输工具，容量、3 英寸搭载/下车范围、运输移动后禁止下车和乘员同步位移都在回放层验证。
单位关键词 `fly` 现在参与移动判定：飞行单位可以越过地形路径，但终点仍须满足桌面边界、地形落点和底座重叠约束。
