# 阶段二：命令协议收口

## 反应射击权威执行

数据策略现在可声明 effect=REACTION_SHOOT、phase=MOVEMENT、timing=AFTER_ENEMY_MOVE，以及整数 hit_on（1–6）。数值来自已加载的策略定义，而非客户端载荷。此机制没有导入官方兵牌或官方策略数据；旧 fire_overwatch 的 REACTION 时机尚未映射，仍明确拒绝。

响应方提交 STRATAGEM 的 id、phase、window_id、attacker_id、target_id、weapon。主机从模型武器表取武器、从策略取命中门槛，重新生成攻击和伤害结果，覆盖任何客户端传入的 attack、damage、hits 等派生字段。目标必须属于刚完成移动的触发单位；普通射程、阵营、预备队/登车、一次性武器及直接射击视线校验仍生效。

主机在策略日志中写入已结算的 attack；回放通过已有 SHOOT 伤害分配流程执行，继承伤害忽略和危险武器处理。校验失败不扣点、不关闭窗口；成功扣点、扣伤并恢复原玩家行动权。主机玩家通过大厅提交策略时也走相同物化入口。面板可选择射手/武器和被移动单位中的目标模型。

额外修复远端信任边界：SHOOT、FIGHT、BATTLE_SHOCK 必须为意图命令，否则拒绝；命令 team 必须匹配已认证房间成员。回放读取权威日志不受此网络入口限制。ADVANCE/CHARGE 等其余掷骰命令的网络物化仍需进一步审计，不能据此宣称全部掷骰入口已完成加固。

## 敌方移动后反应窗口

GRANT_ABILITY 策略可声明 phase=MOVEMENT、timing=AFTER_ENEMY_MOVE。敌方非零 MOVE/FALL_BACK 提交成功后，若另一方在桌模型声明有效且付得起的此类策略，则主机创建 reaction_window：id 为 move:命令序号，包含响应阵营、触发单位与策略 ID 列表。无此类数据时，现有对局不增加等待。

窗口期间原 active_team 不变，但只接受响应方的 STRATAGEM 或新命令 REACTION_PASS，且 payload.window_id 必须匹配。响应策略仍验证友军目标、部署状态、成本和阶段。失败不关闭窗口；成功执行或明确放弃后关闭窗口，恢复原玩家行动权。同一窗口仅一次响应，放弃不扣点。主机按房间身份决定操作阵营，客户端不能伪造响应权。

窗口进入日志和快照，重连保留优先权。本地联机界面提供中文反应面板，可选择策略 ID、友军单位并执行或放弃；非响应方只显示等待。当前范围为联机及权威会话 API 的移动后能力授予反应，不是完整官方反应体系；未新增官方策略数值。单机 AI 暂不接入该窗口。REACTION_SHOOT 尚未有执行器，因此明确拒绝且不扣点，不能再仅记录效果冒充执行。

## 临时能力生命周期与传输 v2

GRANT_ABILITY 的 duration 支持 BATTLE、PHASE、TURN。PHASE 在下次阶段切换或回合结束时失效；TURN 在当前回合结束（含 FIGHT 推进至下一回合）时失效。未到期的重叠授予与原生同名能力保留。模型 ability_grants 保存来源类别及剩余期限；此元数据随权威快照传输，校验器拒绝无效格式。这里的期限是当前回合，不是“下次己方回合”。

网络协议版本升级为 2：PeerProtocol.encode 将 Vector2 转为坐标数组，并规范整数/浮点数哈希，避免 JSON 解码后哈希不一致；接收快照恢复模型 Vector2。双方必须使用新版客户端；旧协议明确拒绝。此次未修改账户凭据、房间或主机权威规则。

验证：Godot **592 项检查，0 失败**；Python **15 项测试通过**。包含真实 JSON 编解码、网络阶段过期、原生能力保留、期限重叠及损坏元数据拒绝。完整中断式反应窗口仍待完成。

## 战斗光环（2026-09-25）

单位、阵营或分遣队能力列表可以包含以下原创测试定义：

```json
{"id":"fixture_guidance","aura":{"radius_inches":6,"event":"before_attack","include_self":false,"keywords":["INFANTRY"],"modifiers":{"hit_rerolls":1}}}
```

运行时保留在模型 ability_ids；FactionRules.combat_modifiers 从当前快照重新计算。范围按来源与目标底座边缘距离，边界含容差；仅同阵营，keywords 中所有关键词均需出现在目标 keywords 或 faction_keywords 中。include_self 默认 true。预备队、登车或伤口为零的来源不发出光环，目标处于这些状态时也不接受光环。来源被移除或超距后不保留效果。同 ID 多来源不叠加，不同 ID 相加；请勿以相同 ID 声明不同效果。

当前支持 before_attack 的 hit_rerolls、hit_reroll_ones、wound_rerolls、wound_reroll_ones，before_defend 的 cover_bonus，objective_control 的 objective_control_bonus，以及 battle_shock 的 leadership_bonus；仅有限非负整数。半径、事件、目标字段与输出字段在数据校验时检查。尚不支持敌方光环、光环视线要求、整单位任一模型入圈共享、通用状态持续时间或任意脚本。

本地玩家射击/近战与网络主机共用动态计算器。命中重掷进入主机实际骰子计算；防御掩体进入目标豁免，修正了原先正掩体值反而增大豁免门槛的问题。回放应用主机日志结果，客户端不提供光环结果、命中或伤害。AI 决策/执行代码未修改，AI 的光环支持暂未接入。

新增回归覆盖范围边界、快照坐标、来源移除/登车/预备队/淘汰、敌我与关键词、叠加、事件隔离、主机骰子计算及结果回放一致。总计 Godot **592 项检查，0 失败**，Python **15 项测试通过**。

目标控制光环也进入任务计分链路。任务控制器在每个目标、每个模型上从当前快照重新计算 objective_control 光环，应用同阵营、底座边缘距离、关键词、阶段与时机条件；权威回放和本地界面使用同一接口，控制结果随比分快照同步。客户端不能上传控制值或比分结果。

## 阵营策略执行增量（2026-09-25）

新增数据效果 `GRANT_ABILITY`：定义必须提供 `target: FRIENDLY_UNIT`、`duration: BATTLE`、固定阶段与相同的 `timing`、以及 `rules/stratagems.gd` 中 GRANTABLE_ABILITIES 列表内的 `ability`。列表现在也包含 `objective_control_plus_1`，因此策略可以通过同一主机、回放和快照路径授予目标控制能力。这是通用原型机制，不是某个阵营的官方规则。

例：`{"id":"fixture_mobility","cost":1,"phase":"MOVEMENT","timing":"MOVEMENT","effect":"GRANT_ABILITY","target":"FRIENDLY_UNIT","duration":"BATTLE","ability":"fall_back_and_shoot"}`。

客户端只需提交 `STRATAGEM` 及 `id`、`phase`、`unit_id`。权威定义取自当前会话中己方模型的 faction_stratagems；客户端载荷里的 ability/effect 不作为执行依据。回放器校验单位归属、已部署且未登车状态后，将能力授予整个附属单位组；能力不重复加入，效果立即标记已消费。扣点与修改原子完成，失败保持原状态。能力保留至本局结束，现支持 PHASE/TURN 临时期限；敌方目标与任意脚本效果仍不支持。

该操作走现有主机 NetworkSync → Room → BattleSession → Replay 路径；回放模型状态与主机一致，快照保留能力。未知 effect 会被拒绝，不能只扣点并记录无实现效果。已有内置效果兼容性保持；其反应窗口扩展仍需后续工作。客户端不得上传攻击结果的边界保持不变。

- 大厅主机玩家使用相同的意图处理入口。旧版客户端需要同步更新。

### 主机私有随机源

所有联机攻击（包括反应射击）、战斗震慑、前进和冲锋均从主机本机 `Crypto.generate_random_bytes` 生成种子，再由 GDScript 随机数生成器物化结果。公开的会话 ID、命令序号和客户端载荷不参与生成种子；私有随机状态不进入快照。重连和回放读取记录的骰面与结果，不重新掷骰。测试可通过主机函数参数注入固定 RNG，网络报文没有该入口。此方案依然信任权威主机，不提供抵抗恶意主机的可验证公平掷骰协议。

### 防御光环与豁免归属

`before_defend` 光环支持 `cover_bonus`、`save_rerolls`、`save_reroll_ones` 和 `invulnerable_save`（2–6）。主机按当前模型位置、敌我、关键词与光环来源实时求值；同 ID 光环沿用不叠加规则。无敌豁免取原生值和能力值中更好的有效门槛。

射击、近战和反应攻击分别传入攻击方与防御方修正，豁免重掷只读取防御方。防御事件收到实际阶段和攻击种类，反应射击不会伪装成射击阶段。结算后的伤害进入权威日志，回放不重新掷骰。新增字段属于通用引擎能力，测试数据为原创夹具，不代表任何已审核官方阵营规则。伤害减免和无视伤害光环尚未在此批接通。

### 光环条件与临时防御策略

光环可声明 `when: {"phase": "SHOOTING", "kind": "SHOOT"}`，按全部条件匹配；缺少上下文时不激活。支持 `phase`（五个标准阶段）和 `kind`（SHOOT/FIGHT），其他字段或非法值会被拒绝。反应射击保留实际 MOVEMENT 阶段，不能获得限定 SHOOTING 阶段的能力。攻击方的命中和伤害修正使用同一次上下文求值。

`GRANT_ABILITY` 现在可授予 `reroll_save`、`reroll_save_ones`、`invulnerable_4`、`invulnerable_5`，沿用 FRIENDLY_UNIT 目标和 PHASE/TURN/BATTLE 期限。防御能力从当前能力列表动态读取，期限结束后立即失效，不缓存到兵牌基础属性。数值为引擎现有通用能力，不表示已确认任何官方阵营的策略数据。

### 策略目标关键词

`GRANT_ABILITY` 与 `REACTION_SHOOT` 可声明 `target_keywords`（全部必需）及 `excluded_target_keywords`（命中任一即禁止），均为字符串数组。条件来自权威策略定义，客户端载荷不能覆盖。前者筛选接受能力的友军单位，后者筛选执行反应射击的友军单位；敌方射击目标仍必须是触发移动的单位。

单位关键词由成员 `keywords` 与 `faction_keywords` 合并，包括附属成员；排除条件优先。主机与回放共用验证，失败保留原状态、CP 和反应窗口。完全没有关键词合格友军单位时不打开该反应策略窗口。窗口存在不保证射程、视线与武器均合法，这些仍在执行时校验；界面按当前策略刷新关键词合格且仍在桌面的单位和射手，射程与视线等剩余条件仍由主机执行时验证。

### 反应面板候选刷新

反应面板与主机反应发现共用 `FactionRules.strategy_recipient_groups`：按阵营、关键词、预备队、登车和存活状态选择友军候选。切换策略即清空并重建目标选项；授予能力显示单位，反应射击显示射手/武器和触发移动的敌方目标。没有可用候选时禁用执行按钮，中文提示说明原因，放弃按钮仍可操作。本批通过场景控件与信号回归验证，未做窗口截图视觉验收。

### 策略使用次数

策略可声明 `usage_limit: {"scope": "PHASE", "max": 1}`。scope 支持 PHASE、TURN、BATTLE，max 为正整数；未声明则保留原有无限次语义，并非自动套用官方规则。每位玩家按策略 ID 单独计数，限额覆盖整个阵营而非每个目标单位。

成功执行后向 `stratagem_usage` 添加使用者、策略 ID、当前行动方、回合计数和阶段。PHASE 按当前行动方/回合计数/阶段匹配，TURN 按当前行动方/回合计数匹配，BATTLE 不跨回合重置。这里的回合计数沿用现有引擎每次玩家回合切换递增的字段，并不新增官方战斗轮机制。失败命令不消耗次数或 CP；临时效果过期不会删除历史用量。记录随快照同步并由回放重建，损坏记录会被会话校验拒绝。用尽的反应策略不再打开新窗口。

### 数据审核边界

导出审核 CSV 新增 `draft_sha256`、`reviewed_by`、`reviewed_at`。批量和直接 CLI 导入均要求显式审核信息以及匹配的草稿摘要，导入结果保存 `review` 元数据。摘要绑定草稿文件字节；它防止误用过期批准，不证明来源数值正确。人工审核仍需核对来源、单位配置、底座与阵营。已批准 CSV 行中的阵营、底座和连结距离是审核输入；修改这些字段同样应重新人工确认。

四类重点问题仍阻止转换：missing_points、missing_weapons、missing_faction_keywords、unsupported_weapon_keywords。当前检出缺少完整 profile_drafts 目录，本批没有重建全部 643 条候选，也没有更改候选复核状态。缺少草稿时导出器返回明确操作提示，不输出空批准表。

### AP 符号约定修正

兵牌及命令引用的武器 `ap` 使用原始带符号整数：0、-1、-2 等，省略等于 0。护甲豁免所需骰面为 `save_on - cover_bonus - ap`，再与有效无敌豁免比较取较好者；无敌豁免不受 AP 或掩体修改。例如 4+ 护甲面对 AP -1 需要 5+，不是之前错误的 3+。规则方向参考 [官方核心规则的 Saving Throw](https://www.warhammer-community.com/wp-content/uploads/2023/06/dLZIlatQJ3qOkGP7.pdf)，不复制长篇规则。

导入保留源 AP 符号；正数 AP 被标为 invalid_weapon_ap，需要人工核对，不能自动取绝对值猜测。运行时兵牌校验也拒绝正数、非整数和非有限 AP。旧日志仍回放已记录结果，不倒算改写历史伤害；新攻击按修正后的豁免算法执行，因此双方需要更新到同一版本。

### 可选 UPnP 接入

`client/nat_mapping.gd` 独立管理阻塞的路由器 API，使用工作线程，主线程只处理状态通知。线程独占网关，建立 600 秒 UDP 租期并每 300 秒续租；关闭使用取消信号，加入/创建另一连接时先关闭旧传输。取消发生在发现期间时不创建映射，映射失败不调用删除，旧任务回调不能恢复已关闭状态。清理或续租失败单独报告，不声称已经成功关闭。退出时等待工作线程完成清理，路由器超时可能延迟退出。

大厅通过 `use_upnp` 可选参数启用，默认 false。映射失败不改变命令信任边界，仍由主机物化并记录骰面与伤害；账号配对、命令包和快照协议保持原状。此功能是路由器映射辅助，不是公网发现、UDP 打洞或中继。验证范围为模拟网关和大厅控件回归，真实网络尚未验收。

### 房间广告与邀请编码

`rules/room_directory.gd` 定义了传输无关的房间广告记录和 `open-battle://join/` 邀请编码。记录只包含房间、规则任务、端点、过期时间和主机公开身份指纹，不包含凭据、密码哈希或重连令牌；大厅可由主机明确提供映射地址或未来中继地址生成邀请。过期、非法端口、端点字符和伪造指纹会在编码前拒绝。它为 HTTPS 目录、局域网发现或中继服务共用同一数据格式，但仓库当前没有部署公网目录或中继服务器，不能把此协议冒称为已完成公网发现。

`tools/room_directory_server.py` 提供了一个依赖零的实验性 HTTP 目录（`POST/GET/DELETE /v1/rooms`），Godot `RoomDirectoryClient` 可调用它查询或发布广告。它只保存公开且会过期的房间广告，不在战斗路径上，不转发 ENet 或命令；生产部署仍需要 TLS、访问控制、限流和持久化策略。独立测试覆盖发布、列表、删除、所有者指纹检查和非法记录拒绝。

`tools/relay_server.py` 提供可选的透明 WebSocket 中继原型：每个房间最多配对一名主机和一名客户端，转发不透明 JSON 帧，不读取或修改规则结果。独立测试覆盖握手、配对、房间/角色隔离和原样转发。Godot 端目前仍是 ENet 直连，中继传输适配器和公网部署安全策略尚未完成，不能把该原型称为完整公网联机。

### 独立进程 ENet 验收

`tests/enet_probe.gd` 和 `tools/test_enet_loopback.py` 提供端到端回环检查。主机与客户端使用内存生成的合成测试身份，不写入真实账号；客户端必须先完成挑战响应，主机再接受 JOIN、READY 和命令。测试确认收到的 `ADVANCE` 已去掉 `intent` 并带有主机骰面，客户端与主机快照哈希一致。测试还主动关闭客户端 ENet，验证主机标记断线、客户端重连并恢复同一会话状态。失败时保留两个进程日志供诊断；不代表真实公网、CGNAT、双重 NAT 或防火墙环境已通过。

### 会话绑定与回环验收补充

主机对 COMMAND 和 RECONNECT 校验 `session_id` 必须等于房间 ID、版本和任务 ID的规范哈希；客户端对 SNAPSHOT 做同样校验。中继或转发层只能转发当前房间会话，不能把一个房间的已认证身份、命令或快照复用到另一房间。房间 ID、玩家身份、命令序号和快照哈希仍分别校验。

端到端回环测试现为独立进程：客户端的命令被主机解析后才进入权威回放，返回快照包含主机生成的骰面；断线后通过保存的地址和重连令牌恢复。该测试使用本机合成账号和临时 UDP 端口，不是公网可达性测试。

### Pending 摘要与候选载荷

`data/units/pending` 的 30 个 JSON 是来源摘要，不是逐条 profile 候选；当前合计 `candidate_count=643`，但 `candidates` 载荷为 0。`index_promotable_candidates.py` 将这 643 条全部记为 `candidate_payload_missing`，输出 `promotable_count=0`，避免审核表或 ready 目录把抽取计数误当确认数据。恢复工作需要重新提供原始来源文件并运行提取器；工具不会从来源名称、页数或阵营名称推断官方数值。

### 重传、跳序与断线保护

主机要求 COMMAND 的 `sequence` 等于当前权威命令日志长度；重复转发和跳序包都返回 `COMMAND SEQUENCE GAP`，不会重新掷骰或改变快照。房间层还要求玩家 `connected=true`，断线玩家只能携带正确重连令牌走 RECONNECT；错误令牌和普通命令均拒绝。序号确认不替代快照哈希、会话 ID、身份和团队校验。

### 可晋升索引与审核表一致性

候选索引器和审核表现在共同阻断 `missing_points`、`missing_weapons`、`missing_faction_keywords`、`unsupported_weapon_keywords`。索引器另外保留 `candidate_payload_missing`，用于来源摘要没有逐条载荷的情况；任何一条缺少阵营关键词或包含未知武器标签都不会进入 `promotable`。该索引只给人工排队使用，不会把结构完整等同于规则已确认。
